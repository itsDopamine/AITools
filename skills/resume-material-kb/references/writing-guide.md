# 写作指南（简历素材向）

## 原则

1. **成就优先**：写做成了什么，少写「负责/参与/了解」
2. **STAR 完整**：缺 Result 的卡片价值很低
3. **具体胜于模糊**：有数字用数字；没有就标 `[待补充量化]`，禁止臆造
4. **可粘贴**：`可粘贴简历分点` 应短、硬、无内部黑话
5. **贡献边界诚实**：主导 / 核心 / 参与 / 学习——写错会被面试拆穿

## 分点格式

```
- **性能优化：**将核心列表接口 P99 从 800ms 降到 120ms
- **方案设计：**推动模板库从单次上传改为可版本管理的素材体系
```

## SWOT（analyses/swot.md）

- Strengths / Weaknesses 必须能从本库卡片找到证据
- Opportunities / Threats 结合目标岗位（未知则写通用研发市场）
- 避免鸡汤；每条下面用括号链到 `works/xx.md`

## 金字塔（analyses/pyramid.md）

```
总结论（1 句）
├── 论据 A → 事实（卡片链接）
├── 论据 B → 事实
└── 论据 C → 事实
```

先结论后展开，方便用户自己决定简历主叙事。

## 项目亮点（project-highlights/）

每篇建议结构：

1. 现象/能力（项目客观存在什么）
2. 为什么难/为什么有价值
3. 我可对外表述的学习收获
4. 贡献边界
